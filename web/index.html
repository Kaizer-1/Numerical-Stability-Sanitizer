The Problem

Floating-point bugs are completely silent.

A float has only 24 bits of mantissa — about 7 significant digits. When you add a tiny number to a huge one, the tiny number simply vanishes. Subtract the huge number back and you get zero instead of the tiny value. The program compiles, runs, and produces output. The output is just wrong. Try it below: enter any two numbers and watch it happen live.

Input Values

float y = (big + tiny) - big;
// should equal tiny

Architecture

How shadow value instrumentation works.

An LLVM function pass rewrites every float operation in the IR. Each original float computation runs alongside an identical computation in double precision. A C runtime library stores shadow values in a hash table keyed by memory address and emits diagnostics whenever the two diverge.

Capabilities

What NSan instruments.

Every instrumented category has at least one dedicated test case demonstrating it works correctly.

Scalar Float Arithmetic
All five IEEE 754 binary operations instrumented. Each float op runs in parallel in double precision.
fadd · fsub · fmul · fdiv · frem · fneg
Shadow Memory
Float loads and stores carry shadow values in a hash table keyed by address. Survives array indexing and struct fields.
load · store · address-keyed table
Control Flow
Shadow propagates through loop-carried PHI nodes, conditional selects, and fptrunc casts.
phi · select · fptrunc
SIMD Vectors
Fixed-width float vectors get per-lane double shadows. Every lane is checked independently with exact source location.
<4 x float> → <4 x double>
Math Function Models
17 libm functions have double-precision shadow models so the shadow doesn't go stale after a math call.
sqrt · sin · cos · exp · log · pow + 11 more
Cross-Function ABI
Thread-local slots propagate float argument and return shadows across non-inlined function calls.
TLS arg slots · TLS return slot
Memory Range Ops
memcpy and memmove transfer shadow state. memset and integer stores invalidate overlapping entries to prevent false positives.
memcpy · memmove · memset
Three Diagnostic Types
Catastrophic cancellation (input/result ratio), float/shadow divergence (threshold), and NaN/Inf mismatch.
cancellation · divergence · NaN/Inf
Tunable at Runtime
All thresholds controlled by environment variables. No recompile needed to tune sensitivity.
NSAN_REL_ERROR · NSAN_CANCELLATION_RATIO
Performance

Benchmark overhead vs. uninstrumented baseline.

Measured on macOS arm64, Homebrew LLVM 22.1.4, 3 iterations each. Overhead varies with float-operation density — the tight scalar loops show ~38× while the vectorised matrix multiply shows only ~5×.

Program Description Baseline Instrumented Overhead
dot_product.c Dot product of two float arrays (N=500k) 0.005989 s 0.226089 s 37.75×
harmonic.c Harmonic sum 1/1 + 1/2 + … + 1/N 0.011756 s 0.449429 s 38.23×
matmul.c Naïve N×N float matrix multiply 0.008148 s 0.041147 s 5.05×
↑ For comparison: Herbgrind (Valgrind-based float analysis) typically reports 100–1000× overhead.
